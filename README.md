# 岩瀬自治会 防災アプリ

## 概要

「岩瀬自治会 防災アプリ」は、地域住民の防災意識向上と災害への備えを支援するために作成したWebアプリです。

自治会活動で得られた防災知識や地域情報を、スマートフォンやパソコンから簡単に確認できるようにまとめています。

特別なアプリのインストールは不要で、Webブラウザから利用できます。

## 🌧 水害マイタイムライン

## 導入手順

### 1. Supabase

Supabase の SQL Editor で `sql/03_community.sql` を実行します。

作成されるもの：

- `surveys` / `survey_questions` / `survey_responses` / `survey_answers`
- `board_posts` / `board_likes`
- `custom_contents`
- RPC … `submit_survey_response` / `create_board_post` / `toggle_board_like` / `get_board_likes`

一般利用者は Supabase Auth を使わないため、**書き込みはすべて RPC 経由**にしています。
テーブルへの直接の書き込みは匿名キーに許可していません。

地区防災計画の画像は既存の `site_contents` テーブルを使い、
`content_type = 'district_plan'` の1行で管理します。
SQLの最後でこの行を自動的に追加します。

### 2. GitHub

このリポジトリの内容をそのまま置き換えてプッシュします。
`sw.js` のバージョンを `2026-09-07-01` に更新済みのため、
利用者側のキャッシュは自動的に作り直されます。

### 3. 動作確認

1. 管理者画面 → 「アンケート」タブ → アンケートを作成し、公開する
2. アプリ → 岩瀬自治会ツール → アンケート → 回答できることを確認
3. 管理者画面 → 「アンケート」タブ → 集計を見る → 回答が反映されることを確認
4. 掲示板に投稿し、いいねが押せることを確認
5. 設定 → 文字の大きさを「特大」にして、他のページにも反映されることを確認

## アンケートについて

### 設問の種類

| 種類 | 内容 |
| --- | --- |
| 単一選択 | 選択肢から1つ選ぶ |
| 複数選択 | 選択肢からいくつでも選ぶ |
| 自由記述 | 文章で回答する |
| 5段階評価 | 1〜5で評価する（事前・事後比較に使う） |

選択肢は管理者画面で1行に1つ入力します。

### 記名と匿名

アンケートごとに、記名・匿名それぞれの可否を設定できます。
両方を許可した場合、回答者が選びます。

- 記名 … 氏名と参加者IDを記録します
- 匿名 … 氏名も参加者IDも記録しません

### 二重回答の防止

同じ端末からの2回目の回答は受け付けません。
端末の識別子は個人を特定するためではなく、
重複を防ぐためだけに使っています。

### CSV出力

集計画面から回答をCSVで書き出せます。
文字化けを防ぐため先頭にBOMを付けています。Excelでそのまま開けます。

事前・事後アンケートの比較や、
年度末の報告書作成に使うことを想定しています。

## お知らせを非公開にできない件について

原因は `announcements` テーブルに UPDATE を許可するポリシー（RLS）が
無かったことと考えられます。

PostgREST は、権限の都合で1行も更新できなかったとき、
エラーではなく「0件更新」を返します。
そのため画面上はエラーが出ず、押しても何も変わらない状態になります。

対応は2つです。

1. `sql/04_announcements_and_comments.sql` で、
   ログイン済みの管理者にすべての操作を許可するポリシーを作り直す
2. 管理者画面側で、更新された行を `select` で受け取り、
   0件だった場合は原因を画面に表示する

2つ目を入れたことで、今後同じことが起きたときに
「押しても変わらない」ではなく理由が分かるようになります。

同じ理由で更新できなくなりやすい `site_contents` と `activities` にも、
同じポリシーを入れてあります。

## PDFで表が重なる件について

原因は2つありました。

1. グラフのCanvasを画像に置き換えるとき、
   画面上の高さ（330px前後）をそのまま指定していた。
   PDF側のグラフ枠は260pxだったため、はみ出して
   次の「参加回数ランキング」に重なっていた
2. PDF用のウィンドウでは画面用のCSSがそのまま効くため、
   「月別参加状況」と「参加回数ランキング」が
   横2列のまま出力されていた

画像は幅100％・高さ自動（縦横比のみ指定）に変更し、
PDF側では2列を縦1列に展開するようにしました。

## 自治会コードについて

| コード | 区分 | 使える機能 |
| --- | --- | --- |
| `iwase2026` | 自治会員 | すべて |
| `iwase` | 会員以外 | 地区防災計画・自治会ツールは不可。活動実績は文字のみ |

コードを変えたくなったときは、
`sql/05` の `resolve_access_code` 関数だけを書き換えてください。
アプリ側のファイルにコードは書いていません。

### 仕組み

既存の `register_or_login_participant` はそのまま残し、
`register_or_login_participant_v2` で包んでいます。

v2 は、入力されたコードから会員区分を判定し、
従来の関数を会員用コードで呼び出したうえで、
`participants.member_type` を更新して結果を返します。

こうすることで、重複防止や氏名＋暗証番号での再開といった
既存の登録処理に手を入れずに済みます。

`sql/05` をまだ実行していない状態でも、
アプリ側は従来の関数へ自動的に切り替わるため、
ログインできなくなることはありません。

### この制限の性質について

これは**画面の出し分け**です。通信内容そのものは守っていません。

活動実績の写真は Supabase Storage の公開URLに置かれているため、
URLを直接知っている人はブラウザで開けます。
既存の自治会コードと同じく、
「関係のない人が普通に使う分には入ってこない」という壁とお考えください。

本当に外に出したくない写真は、
そもそも登録しない運用をおすすめします。

なお、この変更を入れる前に登録した方は全員が
会員用コードで登録しているため、自動的に「自治会員」として扱われます。

# 暗証番号（4桁）の再設定

**Supabase の SQL Editor で `sql/07_pin_reset.sql` を実行してください。**

管理者画面に「暗証番号の再設定」タブを追加しました。

- 氏名で対象者を検索 → 新しい4桁を設定
- 参加者IDは変わらないため、スタンプ・訓練参加記録・防災マイスターの認定は引き継がれます
- 再設定の記録（いつ・どなたの番号を変えたか・対応メモ）が残ります

## できないこと

**元の暗証番号を調べることはできません。** 再設定のみです。

4桁の暗証番号は組み合わせが1万通りしかないため、
データベースを見られる人にとっては秘密として機能しません。
「他人が偶然なりすますことを防ぐ鍵」であって、
パスワードほどの強度は無いという前提で運用してください。

電話などで依頼を受けたときは、氏名だけで本人と判断せず、
生年月日や住所など自治会で把握している別の情報も確認してください。

## 暗証番号の保存方法を知らなくても動く理由

`pin_key` の作り方は `register_or_login_participant` の中にあり、
この関数はダッシュボードで作られているため中身が分かりません。

そこで、次の手順で再設定しています。

1. 対象者と**同じ氏名**・新しい暗証番号で、
   `register_or_login_participant` を使って一時的な登録を1件つくる
2. その一時レコードの `pin_key` を読む（＝正しい作り方で作られた値）
3. 一時レコードを削除する
4. 対象者の `pin_key` をその値に差し替える

平文でもハッシュでも、氏名を混ぜていても同じ結果になります。
氏名を同じにしているのは、`pin_key` の計算に氏名が混ざっている場合に備えるためです。

手順3と4の順序は入れ替えられません。
`(name_key, pin_key)` に一意制約があるため、
一時レコードを消す前に対象者を書き換えると重複エラーになります。

同じ氏名の別の方がその暗証番号を既に使っている場合は、
一時登録の時点で弾かれるので、別の番号を設定してください。

## あわせて修正したもの

`sql/05` の会員区分の更新条件が `participants.id` を見ていましたが、
アプリが使っているのは `participant_id` でした。
`sql/07` の中で修正版に置き換えています（`sql/05` の再実行は不要です）。

アプリ側は登録時の戻り値で会員区分を持つため、
この修正前でも画面の出し分けは正しく動いています。
修正したのは、管理者がデータベース上で会員区分を確認できるようにするためです。

## 地区防災計画のPDF

写真を3枚並べる作りをやめ、次の形にしました。

- **表紙の画像**（1枚）
- **計画のPDF**（ファイルそのもの）

アプリでは表紙が表示され、タップするとPDFが開きます。

### オフラインで読める仕組み

PDFは外部サービスへのリンクではなく、Supabase Storage に置いたファイルを使います。

計画のページを開いた時点で、アプリがPDFを端末に取り込みます。
そのため、**一度開いておけば通信が無いときでも読めます。**

「計画を開く」を押したときも、リンク先へ移動するのではなく、
取り込んだファイルを読み出してから開いています。
リンク先へ移動する形だと、それは別のサイトへの移動になり、
アプリが保存したファイルを使えないためです。

### 運用上のお願い

- **平常時に一度、計画のページを開いておくよう会員の方にお伝えください。**
  一度も開いていない端末では、災害時に通信が無いと読めません
- PDFは20MBまでです。大きすぎると通信の細い場所で開けません
- 表紙の画像は、PDFの1ページ目を画像にしたものが分かりやすいです

### ストレージの設定

PDFは既存の `site-content` バケットに保存します。
Supabase の Storage → site-content → Configuration で
Public bucket が有効になっていることをご確認ください。
アップロードできるファイルの種類を制限している場合は、
`application/pdf` を許可してください。

### 端末による違い

PDFの表示は端末やブラウザの機能に任せています。
iPhone では別のタブで開き、Android では機種によって
PDFを扱うアプリに渡されることがあります。
どちらでも読めますが、見え方は端末によって変わります。

## 利用状況の記録

### 記録するもの・しないもの

記録するのは「どの画面を、いつ、誰が開いたか」だけです。

画面の中で入力した内容は一切記録しません。
アンケートの回答も、掲示板の文章も含みません。

参加者IDを一緒に記録しているのは、
「延べ何回開かれたか」だけでは1人が繰り返し開いたのか
何人が開いたのか分からないためです。

参加者IDを送りたくない場合は、`common/tracking.js` の
`SEND_PARTICIPANT_ID` を `false` にすると、端末の識別子だけになります。

同じ画面を5分以内に何度も開いた場合は1回として数えます。
戻る・進むの繰り返しで数字が膨らむのを防ぐためです。

### 会員の方への説明

記録を始めることは、会員の方にお伝えいただくのが筋だと思います。
「どの機能が使われているかを確認して、使いやすさの改善に使います。
書いた内容は記録しません」という説明で足りるはずです。

### 管理者画面

「利用状況」タブで、期間を選んで集計できます。

- 利用した人数、開いた回数、1人あたりの回数
- 画面ごとの利用（回数と人数）
- 直近14日の日ごとの利用

### 記録の整理

溜め続ける必要はありません。古い記録は次のSQLで消せます。

```sql
select public.purge_page_views(365);
```

## QR読み取りが失敗していた原因

`stamp/training.js` は、利用者情報を **localStorage だけ**から読んでいました。
そのため次の場合に読み取れず、
「先にスタンプカード登録をしてください」と出て止まっていました。

1. **iPhoneの標準QRリーダー**で読み取ると、ホーム画面のアプリではなく
   Safariで開きます。iOSではこの2つは別々の保存領域を使うため、
   アプリ側に保存された情報がSafariからは見えません
2. **プライベートブラウズ**では localStorage が残りません
3. iOSは7日間使わないと保存内容を消すことがあります

5人に1人という割合は、1がいちばん近いと思われます。

### 対応

**利用者情報の探し方を広げました。**
`IwaseIdentity` を使い、localStorage・Cookie・IndexedDB の3か所から復元します。
これで3のケースと、同じブラウザ内での多くのケースは救えます。

**それでも見つからない場合は、行き止まりにせずログイン画面へ送ります。**
お名前と暗証番号（4けた）を入れると、その訓練の登録画面へ戻ります。
1と2のケースはこちらで救えます。ログイン画面へは
`?next=` で戻り先を渡しています。

**登録が終わったらスタンプカードへ移動します。**
すでに登録済みだった場合も同じです。
押した結果が見える場所まで連れて行くようにしました。

### あわせて直したもの

- `stamp/qr.js` が存在しない `stamp/index.html` へ移動しようとしていました。
  `stamp.html` へ直しています（古い形式のQR用のページです）
- 訓練登録画面から「スタンプカードを開く」「トップページへ戻る」で移動する際、
  スタンプカードのURL直打ち防止に引っかからないようにしました

## QRコードのアドレスの確認をお願いします

管理者画面が作るQRコードは、**管理者画面と同じ場所**を基準にしています。

利用者が使うアプリと管理者画面が別のアドレスで公開されている場合、
QRの行き先がアプリと違う場所になり、
利用者情報が引き継がれず失敗することがあります。

**一度スマートフォンでQRを読み取り、アドレスがアプリと同じか確認してください。**

違っていた場合は、`admin/admin.js` の

```javascript
const APP_BASE_URL = "";
```

にアプリ側のアドレス（例：`"https://sugi-18.github.io/iwase-bosai/"`）を入れてください。

# QR読み取りの失敗をなくす仕組み

**Supabase の SQL Editor で `sql/10_training_access_code.sql` を実行してください。**

管理者画面と利用者向けアプリを別のアドレスで公開しているため、
次の3つを組み合わせています。

| 対策 | 何を救うか |
| --- | --- |
| アプリ内のQR読み取り（`stamp/scan.html`） | 標準カメラで開くと別ブラウザになる問題 |
| 受付番号（4桁）での登録 | カメラが使えない・許可しない場合 |
| 古いQRの自動転送 | 配布済みのQRが管理者側を指している場合 |

---

## 1. アプリ内のQR読み取り

「訓練・スタンプ」の一番目に「📷 QR読み取り」を追加しました。

**アプリを開いた状態のまま読み取る**ので、ブラウザが切り替わりません。
利用者情報がそのまま使えるため、失敗しません。

当日のご案内は「アプリを開いて、QR読み取りを押してください」の一言で足ります。

読み取りには `jsQR` を使っています（CDNから読み込み）。
カメラの許可は初回に一度だけ必要です。

---

## 2. 受付番号（4桁）

同じ画面の下半分に、番号を入力する欄を置いています。

管理者画面でQRコードを表示すると、その訓練の受付番号が一緒に表示されます。
番号は訓練ごとに1つ発行され、一度決まったら変わりません。
配った紙と食い違わないようにするためです。

**カメラの許可を求められるのが苦手な方には、こちらのほうが速いと思います。**
受付にQRと一緒に「受付番号 1234」と大きく掲示しておくと、
QRが読めない方はそこで解決します。

古い番号で登録されないよう、実施日から前後14日の訓練だけを受け付けます。

---

## 3. 古いQRコードの自動転送

配布済みのQRコードは、管理者側のアドレスを指しています。

`stamp/training.html` の先頭に、管理者側で開かれた場合は
利用者向けのアドレスへ送り直す処理を入れました。
**配った紙を刷り直す必要はありません。**

これから作るQRコードは、はじめから利用者側を指します
（`admin/admin.js` の `APP_BASE_URL`）。

### アドレスが違う場合

この2か所に、利用者が使うアプリのアドレスを設定しています。

```javascript
// admin/admin.js
const APP_BASE_URL = "https://sugi-18.github.io/iwase-bosai/";

// stamp/training.html（先頭のscript内）
var APP_BASE_URL = "https://sugi-18.github.io/iwase-bosai/";
var ADMIN_MARK   = "iwase-bosai.adm";
```

公開しているアドレスが違う場合は、両方を書き換えてください。
`ADMIN_MARK` は、管理者側のアドレスに含まれていて
利用者側には含まれない文字列です。

2. うまくいかない方は、受付番号（4桁）を入力
